[![Python](https://img.shields.io/badge/Python-3.10%2B-blue)](https://www.python.org/)
[![License](https://img.shields.io/badge/License-MIT-green)](LICENSE)

> [🇬🇧 **Read in English**](README.md) • [🇪🇸 **Leer en español**](README_es.md)

Асинхронный бот, который автоматически фармит **поинты каналов** и майнит **дропсы** на **Kick.com**. Поддерживает несколько аккаунтов, приоритеты, прокси и уведомления в Telegram / Discord.

> [!WARNING]
> **Форк, разработанный с помощью ИИ.** Изменения в этом форке реализуются с помощью ИИ. Поэтому в нём могут быть баги, неожиданное поведение или ошибки.

## ✨ Возможности

*   **👥 Мультиаккаунт:** Фарм с нескольких аккаунтов одновременно, у каждого свой список стримеров, лимиты и прокси.
*   **🎯 Система приоритетов:** Стримеры приоритизируются по позиции в конфиге. Стример с более высоким приоритетом, вышедший в эфир, вытесняет стримера с более низким.
*   **🎁 Майнинг дропсов:** Отслеживает кампании дропсов Kick через WebSocket (без браузера), использует реальный прогресс Kick как источник истины, получает награды и автоматически переключает каналы.
*   **🔀 Приоритет дропсов:** Кампании и игры ранжируются в том порядке, в котором вы их записали. Если во время просмотра менее приоритетного варианта становится доступен **более приоритетный**, майнер сразу переключается на него.
*   **🔒 Лимит одновременных просмотров:** `max_concurrent` на аккаунт задаёт, сколько стримеров смотреть одновременно, и помогает избежать ограничений 403.
*   **🌐 SOCKS5 / HTTP прокси:** Глобальный или для каждого аккаунта.
*   **🛡 Обход Cloudflare:** Управление сессиями на базе `curl_cffi` с повторами при 403.
*   **📱 Уведомления в Telegram и Discord:** Только отправка (они никогда не слушают команды). Каждый тип события включается и отключается независимо.
*   **🌍 Мультиязычность:** Английский, русский и испанский.
*   **📉 Чистое логирование:** Читаемый вывод в консоль с опциональным Debug-режимом.
*   **♻ Без утечек памяти:** Сессии переиспользуются и корректно закрываются, при долгой работе утечек нет.

## 🔑 Как получить токен Kick

1.  Зайдите на **Kick.com** и авторизуйтесь в браузере.
2.  Нажмите `F12`, чтобы открыть инструменты разработчика.
3.  Перейдите на вкладку **Network** (Сеть).
4.  Обновите страницу (`F5`).
5.  Нажмите на любой появившийся запрос (например, `auth`).
6.  В правой панели откройте **Headers** (Заголовки) и прокрутите до **Request Headers**.
7.  Найдите строку `authorization`.
8.  Скопируйте длинную строку, которая идёт **после** слова `Bearer`. Она выглядит так: `123456789|************************************`.
9.  Вставьте её в поле `"token"` вашего `config.json`.

## 🎮 Использование

```bash
python main.py
```

Майнер будет:

1. Загружать все аккаунты из конфига.
2. Принимать первое решение по дропсам (если они включены).
3. Проверять, кто из стримеров онлайн.
4. Подключаться к топ-N стримерам (по приоритету) для каждого аккаунта.
5. Динамически перебалансировать при выходе стримеров в онлайн и оффлайн.
6. Автоматически перезапускаться при сбоях.


## 🎁 Майнинг дропсов

Отслеживает **кампании дропсов** Kick за вас. Дропсы **выключены**, пока `Drops.enabled` не равно `true`.

### Как это работает

1. Запрашивает у Kick активные кампании и ваш *реальный* прогресс в каждой.
2. Ранжирует ожидающие кампании по приоритету (см. ниже) и выбирает лучшую, у которой есть канал в эфире. Истёкшие и уже полученные пропускаются.
3. Смотрит этот канал. **Источник истины — прогресс Kick**: он перечитывается каждые `check_interval` секунд.
4. Если стример ушёл в оффлайн, сменил игру или перезапустил стрим, майнер переходит на другой канал кампании.
5. Если становится доступна кампания с **более высоким приоритетом**, майнер сразу переключается на неё.
6. Награды, достигшие 100 %, получаются автоматически, когда `auto_claim` равен `true`.
7. Когда всё завершено или никто подходящий не в эфире, возобновляются поинты каналов.

Kick засчитывает дропсы только с одного стрима за раз, поэтому каждый аккаунт смотрит **один** канал дропсов. Пока у дропсов есть работа, они имеют приоритет над поинтами каналов; стример из вашего списка переиспользуется для дропсов, если подходит.

### Приоритет (`campaigns` и `games`)

Приоритет — это единая лестница, построенная из вашего конфига. **Меньшая позиция = более высокий приоритет.**

1. Записи `campaigns` в том порядке, в котором вы их написали.
2. Записи `games` в том порядке, в котором вы их написали.
3. Всё остальное (только когда фильтры не заданы).

Таким образом, кампания из `campaigns` всегда выше игры из `games`, а внутри каждого списка побеждает первая запись.

```json
{
  "Drops": {
    "enabled": true,
    "campaigns": ["Special Event"],
    "games": ["Rust", "Valorant"]
  }
}
```

Итоговый порядок: `Special Event` → `Rust` → `Valorant`.

#### Что можно писать в `campaigns` и `games`

Оба поля — обычные списки текста. Сравнение **не чувствительно к регистру** (`"rust"` и `"Rust"` — одно и то же) и сначала ищет **точное совпадение**; только если ничего не совпало точно, используется вариант «название содержит этот текст».

| Список | Чем может быть запись | Пример записи | Чему соответствует |
| :--- | :--- | :--- | :--- |
| `campaigns` | Точное название кампании, как его показывает Kick | `"Rust Twitch Drops - Winter Chill"` | Только эта конкретная кампания |
| `campaigns` | Часть названия кампании (резервный вариант, если нет точного совпадения) | `"Winter Chill"` | Любая кампания, в названии которой есть «Winter Chill» |
| `campaigns` | Внутренний id кампании (нужен редко; виден в самой странице/API дропсов Kick) | `"a1b2c3d4-..."` | Только эта конкретная кампания |
| `games` | Точное название игры | `"Rust"` | Любая активная кампания игры «Rust» |
| `games` | Часть названия игры (резервный вариант) | `"Counter"` | Любая игра, содержащая «Counter», напр. «Counter-Strike 2» |

Не обязательно угадывать точное написание: если вы напишете то, что не совпадает точно ни с одной кампанией или игрой, майнер всё равно сработает, если это достаточно уникальный фрагмент текста — но точное название всегда безопаснее и исключает случайные совпадения (см. пример «Rust» против «Trust Fall» ниже).

#### Примеры

**Только игры, по приоритету** — майнить любую кампанию для этих игр, Rust первым:
```json
{ "Drops": { "enabled": true, "games": ["Rust", "Valorant", "Counter-Strike 2"] } }
```

**Только конкретные кампании, по приоритету** — игнорировать всё остальное, даже другие кампании тех же игр:
```json
{ "Drops": { "enabled": true, "campaigns": ["Winter Chill Drops", "Summer Bash Drops"] } }
```

**Смешанный вариант: кампании выше игр** — `campaigns` всегда выше `games`, независимо от того, в каком порядке вы написали эти два списка в JSON-файле:
```json
{
  "Drops": {
    "enabled": true,
    "campaigns": ["Special Anniversary Event"],
    "games": ["Rust", "Valorant"]
  }
}
```
Приоритет здесь: `Special Anniversary Event` (1-й) → `Rust` (2-й) → `Valorant` (3-й) → всё остальное игнорируется.

**Совсем без фильтров** — майнить все активные кампании, которые предлагает Kick, в том порядке, в котором их возвращает Kick (без особого приоритета):
```json
{ "Drops": { "enabled": true } }
```

**Одна игра, приоритет не нужен** — список из одного элемента тоже работает:
```json
{ "Drops": { "enabled": true, "games": ["Fortnite"] } }
```

Правила:

*   **Сначала точное совпадение.** Название сравнивается точно (id кампании, полное название кампании, полное название игры), и только при отсутствии точного совпадения используется «содержит». Поэтому `games: ["Rust"]` точно совпадает с игрой «Rust» и **не** захватывает по ошибке никак не связанную игру «Trust Fall» только потому, что «rust» является подстрокой «trust» — проверка на точное совпадение с «Rust» срабатывает первой.
*   **Переключение только вверх, никогда вниз.** Более важная кампания вызывает немедленное переключение, как только один из её каналов в эфире. Менее важная никогда не прерывает работающую сессию.
*   **Несколько каналов одной кампании** равнозначны: любой из них даёт одинаковый прогресс, поэтому майнер между ними не прыгает.
*   **Неудачное переключение безопасно.** Если лучший канал не удалось открыть, майнер возвращается на прежний канал и пробует снова при следующей проверке.
*   Если **не** заданы ни `games`, ни `campaigns`, майнятся все активные кампании в том порядке, в котором их возвращает Kick.

### Параметры дропсов

| Параметр | Описание |
| :--- | :--- |
| `enabled` | Главный переключатель. `false` (по умолчанию) оставляет майнер без изменений. |
| `campaigns` | Майнить только эти кампании (id или название). **Порядок — это приоритет**, они стоят выше `games`. |
| `games` | Майнить только кампании этих игр. **Порядок — это приоритет.** |
| `auto_claim` | `true` автоматически получает награды при достижении 100 %. `false` лишь сообщает, что они готовы. По умолчанию `false` в коде (`config.example.json` поставляется с `true`). |
| `claim_retry_seconds` | Пауза перед повтором неудачного получения, например для непривязанного игрового аккаунта (по умолчанию `1800`, минимум `300`). |
| `check_interval` | Секунды между проверками прогресса и статуса (по умолчанию `300`, минимум `60`). |
| `max_global_streamers` | Для глобальных кампаний — сколько топ-стримеров игры в эфире рассматривать (по умолчанию `24`). |
| `offline_checks_to_switch` | Сколько «оффлайн»-проверок подряд до ухода с канала (по умолчанию `2`). |
| `points_grace_seconds` | Когда дропсы потеряли канал, а кампания ещё ожидает, — как долго поинты каналов остаются на паузе (по умолчанию `600`). |

Весь блок можно переопределить **для каждого аккаунта**:

```json
{ "alias": "Main", "token": "...", "streamers": ["a"], "drops": { "enabled": true, "games": ["Rust"] } }
```

### Два типа кампаний (определяются автоматически)

*   **Кампании по каналам:** засчитываются только стримеры из списка Kick.
*   **Глобальные кампании:** засчитывается любой стример игры; майнер выбирает тех, кто в эфире, из категории игры.

### Получение наград

*   Каждая награда получается один раз. Неудача повторяется только через `claim_retry_seconds`.
*   Если Kick просит **привязать игровой аккаунт** (например, аккаунт издателя), майнер один раз сообщит об этом и покажет ссылку. Привязать его за вас он не может.
*   При `auto_claim: false` вас уведомят, когда награда готова, и вы получаете её сами на kick.com.

### События дропсов

И `Telegram.drops_events`, и `Discord.drops_events` принимают эти ключи (независимо, по умолчанию все `true`):

`started`, `stopped`, `progress`, `priority_switch`, `reward_ready`, `reward_claimed`, `claim_unavailable`, `claim_needs_link`, `claim_failed`, `campaign_finished`, `no_pending`, `no_live_channel`, `category_changed`, `stream_restarted`, `refresh_failed`, `loop_error`, `progress_unavailable`, `global_no_category`, `wrong_category`.

`include_category_in_points` добавляет текущую категорию стрима в каждое уведомление о поинтах. Поинты, полученные на канале только для дропсов, отправляются тем же сообщением и помечаются `Drops mining`.

### Благодарности

Интеграция дропсов вдохновлена [KickDropsMiner](https://github.com/HyperBeats/KickDropsMiner). У этого проекта собственная реализация API / WebSocket, он не связан с тем проектом.

## 📱 Уведомления в Telegram

Интеграция работает **только на отправку**: она посылает лог-сообщения на `chat_id`, точно так же, как вебхук Discord. Она никогда не слушает обновления, и команд у неё нет.

### Как получить `bot_token` и `chat_id`

Нужны два значения: **токен бота** (идентифицирует вашего бота) и **chat id** (говорит боту, куда отправлять сообщения, то есть вам).

1.  **Создайте бота и получите `bot_token`:**
    1. Откройте Telegram и найдите **@BotFather** (официальный бот, создающий других ботов).
    2. Отправьте `/newbot`.
    3. Выберите отображаемое имя для бота (любое, например `My Kick Miner`).
    4. Выберите **username** для него — он должен быть уникальным и заканчиваться на `bot` (например `my_kick_miner_bot`).
    5. BotFather ответит сообщением с токеном вида `123456789:ABCdefGhIJKlmNoPQRsTUvwxYZ`. Вся эта строка и есть `bot_token`.
2.  **Начните чат с ботом и получите `chat_id`:**
    1. Найдите своего бота по выбранному username и откройте его.
    2. Нажмите **Start** (или отправьте любое сообщение, например `привет`). Этот шаг обязателен — бот не может написать вам первым.
    3. В браузере откройте `https://api.telegram.org/bot<TOKEN>/getUpdates`, заменив `<TOKEN>` на ваш `bot_token` (сохраните префикс `bot`, например `https://api.telegram.org/bot123456789:ABCdef.../getUpdates`).
    4. Найдите в JSON-ответе `"chat":{"id":123456789,...}`. Это число и есть ваш `chat_id`.
    5. Если ответ пустой — `{"ok":true,"result":[]}` — вы пропустили шаг 2: напишите боту сообщение и обновите страницу.
3.  **Вставьте оба значения** в `config.json` → `Telegram.bot_token` и `Telegram.chat_id`, и поставьте `Telegram.enabled` в `true`.

> **Групповые чаты:** чтобы уведомлять группу вместо себя, добавьте бота в группу и используйте id группы (отрицательное число) в качестве `chat_id`. Метод `getUpdates` выше работает так же, как только бот получит сообщение в этой группе.

```json
{
  "Telegram": {
    "enabled": true,
    "bot_token": "YOUR_TELEGRAM_BOT_TOKEN",
    "chat_id": "YOUR_TELEGRAM_USER_ID",
    "notify_points": true,
    "notify_status_change": true,
    "notify_errors": true,
    "notify_startup": true,
    "notify_restart": true,
    "notify_daily_reward": true,
    "min_points_gain": 10,
    "send_daily_reward_card": false
  }
}
```

| Параметр | Описание |
| :--- | :--- |
| `bot_token` | Получите у @BotFather. |
| `chat_id` | Ваш личный chat / user ID в Telegram. |
| `notify_points` | Уведомлять при начислении поинтов. |
| `notify_status_change` | Уведомлять, когда стримеры выходят в онлайн / оффлайн / вытесняются. |
| `notify_errors` | Уведомлять об ошибках. |
| `notify_startup` | Отправлять сводку при запуске. |
| `notify_restart` | Уведомлять при остановке или перезапуске майнера. |
| `notify_daily_reward` | Уведомлять о наградах ежедневного задания. |
| `drops_events` | Выбор отправляемых событий дропсов (см. [События дропсов](#события-дропсов)). |
| `include_category_in_points` | Добавлять категорию стрима в уведомления о поинтах. |
| `min_points_gain` | Минимальный прирост, вызывающий уведомление о поинтах. |
| `send_daily_reward_card` | Отправлять карточку ежедневной награды как настоящее фото. По умолчанию `false` (только текст). |

Все флаги `notify_*` по умолчанию `true`. Поставьте любой в `false`, чтобы отключить только этот тип события.

Вы будете получать сообщения о:

*   🚀 Запуске майнера: `notify_startup`
*   💰 Начисленных поинтах по каждому стримеру: `notify_points`
*   👁 Изменении статуса стримеров: `notify_status_change`
*   🎁 Событиях дропсов: `drops_events`
*   ❌ Ошибках: `notify_errors`
*   🎉 Полученной ежедневной награде (нужен `ClaimDailyReward`): `notify_daily_reward`
*   🔄 Остановках / перезапусках: `notify_restart` (отправляется синхронно прямо перед завершением процесса, поэтому доходит даже при Ctrl+C)

## 🎯 Получение ежедневной награды

Автоматически проверяет и получает ежедневное игровое задание Kick (награда за время просмотра + приз рулетки) для каждого аккаунта и публикует результат в Discord и / или Telegram.

**Как это работает (без фиксированного интервала опроса):**

1. При запуске, сразу после получения награды или в начале окна нового дня один раз запрашивается у Kick, сколько минут просмотра ещё не хватает.
2. После этого время учитывается только локально и только пока аккаунт реально смотрит стрим. Если смотреть нечего, задание не может продвигаться, поэтому запросы не выполняются.
3. Когда накопленное время достигает нужного значения, выполняется повторная проверка и награда получается автоматически.
4. После получения награды за день API больше не запрашивается до начала следующего окна.

```json
{ "ClaimDailyReward": false }
```

`ClaimDailyReward` — простой переключатель вкл / выкл (по умолчанию `false`). Публикуется ли событие и прикладывается ли картинка карточки, определяется настройками самого канала: `notify_daily_reward` и `send_daily_reward_card`.

Уведомление показывает подтверждение получения, редкость награды (с картинкой карточки только если `send_daily_reward_card` равен `true`) или, если такая карточка у вас уже была, дополнительные минуты просмотра, полученные взамен.

## 🐳 Docker и Portainer

Рекомендуемый способ запуска майнера в фоновом режиме, например на домашнем сервере, NAS или любой машине с **Portainer**.

**Требования:** установленный [Docker](https://docs.docker.com/get-docker/) и рабочий `config.json` (сначала скопируйте `config.example.json` и отредактируйте его).

### Вариант 1: Docker CLI

```bash
# 1. Соберите образ (из корня проекта)
docker build -t kick-channel-points-miner .

# 2. Запустите контейнер
docker run -d \
  --name kick-miner \
  --restart unless-stopped \
  -v "$(pwd)/config.json:/app/config.json:ro" \
  kick-channel-points-miner
```

### Вариант 2: Docker Compose

```bash
# config.json должен лежать в той же папке, что и docker-compose.yml
docker compose up -d
```

Остановить: `docker compose down` · Логи: `docker compose logs -f`

### Вариант 3: Portainer (GUI)

Следуйте этой инструкции: <https://github.com/Baillora/Kick_Channel_Points_Miner/issues/4#issuecomment-3944659440>

> **Совет:** контейнер автоматически перезапустится при сбое или перезагрузке сервера благодаря `restart: unless-stopped`.

> **Безопасность:** `config.json` **никогда не встраивается в образ**. Он всегда монтируется во время выполнения, поэтому ваши токены остаются только на вашем хосте.
